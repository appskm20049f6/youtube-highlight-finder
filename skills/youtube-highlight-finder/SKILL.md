# YouTube 精華挑選

## 目標與預設

使用者提供 YouTube 網址後，完成「下載影片 → 擷取語音 → 產生字幕 → 從字幕挑選精華」並交付檔案。預設每支影片挑選 5～10 個片段，不剪接、不輸出精華影片。若使用者另指定數量、觀眾、主題或片長，依其要求執行。

**成功下載完整影片並擷取 WAV 是必要條件。** 不得自行降級為只讀網頁字幕；除非使用者明確改為只分析字幕，否則字幕清單只能標示為中間成果，整個流程仍未完成。

## 必要工具、下載與版本檢查

執行前檢查實際可執行檔路徑與版本，不只檢查工具名稱。缺少必要工具時，在當次授權允許的範圍內從官方來源或可信套件管理器安裝，優先使用工作區隔離環境。依安裝來源更新同一套工具，避免 PATH 中的舊版本遮蔽新版。安裝及更新後再次執行版本命令並記錄結果。不要要求使用者自己執行你能執行的檢查。

| 項目 | 必要性與檢查 | 取得方式 |
| --- | --- | --- |
| yt-dlp | 必須；`yt-dlp --version`，比較官方目前發布版本 | 獨立版用 `yt-dlp -U`；pip 環境用 `python -m pip install -U "yt-dlp[default]"`；套件管理器安裝者用原管理器升級。官方：https://github.com/yt-dlp/yt-dlp |
| FFmpeg 與 ffprobe | 必須；`ffmpeg -version`、`ffprobe -version` | 透過 https://ffmpeg.org/download.html 指向的平台來源或可信套件管理器，確認兩者皆可執行 |
| JavaScript runtime 與 EJS | 依目前 yt-dlp 的 YouTube 要求檢查並補齊；優先 Deno，`deno --version`，並檢查 yt-dlp verbose 診斷中的 runtime/EJS 警告 | https://github.com/yt-dlp/yt-dlp/wiki/EJS；官方獨立版與 pip default extra 的 EJS 包裝不同，按當前官方文件確認，不猜測參數；Deno 官方 https://deno.com/ |
| Python、faster-whisper 與模型 | 沒有可靠原語言字幕時必須；`python --version`、`python -m pip show faster-whisper`，確認模型能實際載入 | 使用隔離 Python 環境安裝 `faster-whisper`；官方 https://github.com/SYSTRAN/faster-whisper 。優先既有模型；無模型時下載適合硬體及語言的模型，CPU 可用 int8。不得默默使用付費轉錄服務 |
| 影片、音軌與原語言字幕 | 必須取得含畫面與聲音的完整影片，分離音軌下載時必須合併；字幕可下載或從 WAV 轉錄 | 用 yt-dlp 列出音軌、格式和字幕，再選實際語言；YouTube 自動翻譯字幕不能充當原語言逐字稿 |

將工具與模型下載大小、可能耗時的估計告知使用者，但已授權且可執行的必要準備直接完成。cookie 與登入資料不是可公開下載的依賴；需使用瀏覽器登入 cookie 時，先確認目前授權是否涵蓋該帳號與資料，不把 cookie 寫入成果、GitHub 或診斷輸出。

## 下載故障診斷

先保存去除敏感資料的錯誤摘要，再依原因修復，不用反覆更換格式代替診斷：

1. 出現 403、簽章／JS challenge 警告或沒有可用影音格式時，檢查 yt-dlp 版本、runtime、EJS 與 `yt-dlp --verbose --list-formats URL`。按官方文件更新與補齊依賴；最新版 stable 仍有相同錯誤時，可依官方建議使用官方 nightly（獨立版 `yt-dlp --update-to nightly`，pip 用 `python -m pip install -U --pre "yt-dlp[default]"`），記錄版本變更，再以新取得的來源資訊重試。無證據時不能斷言是 IP、帳號或電腦問題。
2. 429 時遵守服務提供的等待時間，暫停密集請求；一次只下載需要的原語言字幕，不批量下載翻譯語言。
3. 格式／合併失敗時依實際格式清單選擇畫面與音軌，檢查 FFmpeg。完整下載後以 ffprobe 驗證 video/audio streams、合理時長，再做可解碼檢查；`.part`、空檔和只含畫面的檔案都不算成功。
4. 若服務明確要求登入或帳號存取，依授權處理正常登入，不能繞過存取限制。三次有依據的修復仍失敗時，停止同一問題的重試，指出尚未證實的假設與所需外部條件；保留已完成檔案，標示下載步驟阻塞。工具補齊或其他新證據改變條件後，才開始新的診斷回合。

沒有網址時，只問一個問題：請提供要分析的 YouTube 影片連結。已有網址時直接開始。預設保留原語言，使用繁體中文寫精華標題與理由；不把翻譯當成逐字原文。

## 執行流程

1. **確認來源並下載影片。** 記錄來源網址、標題、影片 ID、時長。檢查現有 `yt-dlp`、`ffmpeg`、`ffprobe` 和可用的語音辨識工具，選擇已可用的工具。需要查閱用法時，使用官方文件。用獨立工作目錄，以影片 ID 命名，避免覆寫既有檔案。網址以參數安全傳入，避免插入可執行的 shell 字串。優先下載包含音軌的 MP4 或可合併的影音格式；只需分析時不必下載最高解析度。下載失敗時保留錯誤原因，不繞過存取限制；可改用使用者提供的本機影片。
2. **擷取語音檔。** 從下載影片匯出單聲道、16 kHz WAV，從原始影片的 00:00:00 開始。不要刪除靜音、調速或移除開場，避免字幕時間碼偏移。用工具確認音檔可讀且時長與來源相符。
3. **產生含時間碼的字幕。** 優先使用與實際語音一致的原語言 YouTube 字幕；無合適字幕時，使用可用的語音辨識工具從音檔轉錄。需下載模型或使用付費服務時，遵守目前授權與工具規則；缺少辨識能力時明確報告阻礙，不假裝已轉錄。記錄字幕來源是人工字幕、自動字幕或音檔辨識。輸出 UTF-8 SRT，包含序號、`HH:MM:SS,mmm --> HH:MM:SS,mmm` 和原文。分段辨識時，將每段的起始偏移加回時間碼。合併自動字幕的滾動重複文字時，保留對應的原始時間範圍。無法辨認處標示，不猜測。
4. **閱讀全篇字幕並挑選精華。** 長影片可分批讀取，但先涵蓋完整影片，建立候選，再合併去重與排序。預設挑 5～10 段；選擇資訊密度高、具有明確觀點、具體案例、故事轉折、實用步驟或情緒張力，而且能獨立理解的內容。避免廣告、重複段落、只有鋪陳而沒有結論的片段。不要強行湊滿；素材不足時交付實際有品質的數量並說明。未指定片長時，通常以 30～120 秒為候選範圍，依完整語意調整。片段需有完整開頭與收尾，涵蓋必要上下文；同一論點只留最佳片段，避免大量重疊。以字幕支持選擇，不宣稱已驗證畫面表情或視覺效果。
5. **驗證並交付。** 確認 SRT 可解析，時間碼非負且順序合理，結束不早於開始且不超出影片時長。確認每段引文確實來自對應字幕範圍，時長計算正確。可使用音訊工具時，抽查至少開頭、中段、結尾的對齊；未能聽音驗證則標示時間碼仍需試聽確認。交付原影片、WAV、SRT、精華清單 Markdown 及 CSV。中間檔放 `work/`，使用者交付檔放目前工作區 `outputs/`，並提供可點擊的絕對路徑。

## 精華清單格式

開頭記錄來源網址、影片標題、時長、字幕來源與精華數量。依推薦優先度排列，每段包含：

- 排名與短標題。
- 原影片開始時間、結束時間及片段時長，顯示到秒。
- 原文摘錄：引用字幕中的關鍵句；提供字幕序號範圍以便回查，省略處明確標示。
- 入選理由：具體指出看點、觀眾能得到的收穫與必要上下文。
- YouTube 時間連結：以原網址加上該段起始秒數；保留原網址既有參數。

CSV 欄位：`rank,title,start,end,duration_seconds,subtitle_start_index,subtitle_end_index,excerpt,reason,youtube_url`。含逗號、引號或換行的欄位必須正確引用，使用 UTF-8 BOM 方便 Excel 開啟。

## 完成標準

只有實際存在且驗證可讀的檔案才能說已產生。完成前逐一確認完整影片含畫面與音軌、從該影片擷取的 WAV、原語言 SRT、精華 Markdown 與 CSV 均存在且可讀；缺少任何一項就不得宣告流程完成。翻譯字幕可作補充，但不能取代逐字稿。工具失敗時指出失敗步驟、原因與可行下一步，保留已完成的檔案。同一問題嘗試三次仍失敗時停止重試，指出需要確認的假設。不得把僅閱讀網站文字說成已下載影片，也不得把無時間碼摘要說成字幕檔。
